# Frontend security sequencing amendment

**Date:** 2026-08-18

**Status:** Approved, bounded amendment

**Decision owner:** Project owner
**Affected work:** M2-06, M2-GATE, M4-10

## Context

The exact M2-06 resolved dependency graph still contains critical and high
findings rooted in the retained Create React App 4 management-console toolchain,
its legacy browser authentication dependency, Enzyme-era test tooling, and the
retired Docusaurus 1 website workspace. The approved vulnerability policy covers
resolved production and development dependencies and therefore correctly blocks
M2-GATE. Deferring those dependencies until after M3-GATE creates a dependency
cycle: M3 cannot start before M2-GATE, while the remediation was originally
assigned to M4-10 after M3-GATE.

The project owner directed delivery to continue through all milestones after the
agent presented a choice between short-lived exact security exceptions and a
bounded sequencing change. Remediation was selected; no vulnerability exception
or policy weakening is approved.

## Decision

Pull forward only the security and toolchain foundation of M4-10 so that it is a
prerequisite of M2-GATE:

- replace Create React App with Vite;
- replace Enzyme with Testing Library;
- upgrade React and Ant Design compatibly;
- remove the legacy browser OIDC and obsolete build/test dependency graph;
- preserve characterized management-console behavior, routing, forms, CSP, and
  server embedding contracts; and
- remove the retired website package from the installable Yarn workspace graph
  while retaining its historical source and documentation.

M4-10 may be implemented on the M2-06 candidate because its resolved graph is
required evidence for M2-06 and M2-GATE. M4-11 routing/forms modernization and
M4-12 workflow UI remain after M3-GATE. No M3 schema, API, authorization, or
runtime-command work is pulled forward.

## Consequences and controls

- M2-06 remains incomplete until a fresh recursive audit and the full policy
  evidence accept the exact combined graph.
- M4-10 is not Done merely because dependencies install: frontend build,
  component tests, serve/embedding smoke, and dependency searches must pass.
- Existing UI behavior is preserved rather than redesigned.
- Critical/high exceptions remain unavailable unless separately approved under
  `docs/security/vulnerability-license-policy.md`.
- If the frontend migration cannot remove the blocking graph without changing
  deferred product behavior, work stops for another owner decision rather than
  weakening the M2 gate.

## Rollback

Revert the M4-10 commits and this amendment together. That restores the original
sequencing but also restores the documented M2 blocker; it does not authorize
passing M2-GATE.
