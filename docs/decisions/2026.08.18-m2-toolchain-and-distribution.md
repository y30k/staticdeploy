# M2 Toolchain, Distribution, and Vulnerability Contracts

**Status:** Approved for local implementation

**Tracker:** [M2-01 / issue #28](https://github.com/y30k/staticdeploy/issues/28)

**Decision date:** 2026-08-18

## Decisions

### Runtime and workspace tooling

- Pin Node `24.19.0` exactly in repository metadata, CI, and container builders.
- Migrate from Yarn Classic `1.22.x` to Yarn `4.18.0` using the `node-modules`
  linker.
- Upgrade the root task runner from Lerna `4.0.0` to Lerna `10.0.0` and remove
  redundant workspace-local Lerna declarations.
- Rename the private root package to `@staticdeploy/monorepo` because Yarn 4
  rejects its duplicate name with the service workspace.
- Remove `useWorkspaces` from `lerna.json`; Lerna 10 reads package-manager
  workspaces directly.
- Use immutable installs and commit the converted Yarn lockfile.
- Do not merge with global install-script execution enabled. M2-02 owns an exact
  package/version/script inventory and must enforce it through Yarn
  `dependenciesMeta` or an equivalently narrow supported mechanism. Any newly
  resolved script is blocked pending review. M2-GATE verifies that broad
  `enableScripts: true` is absent.
- Allow a build-only `NODE_OPTIONS=--openssl-legacy-provider` bridge for the
  legacy CRA/Webpack 4 console only when scoped to that build command. M4-10
  must remove the bridge by replacing CRA/Webpack 4.

Yarn/Lerna is selected over pnpm because it changes fewer primary repository
contracts while moving both tools to supported releases. pnpm remains
technically feasible but its prototype required a 20-path manifest/script
migration, `shamefullyHoist`, explicit workspace linking, and lifecycle
approvals before reaching the same application-level gates.

### Artifact and compatibility disposition

The only approved M2 product artifact is one hardened multi-architecture service
OCI image. Publication remains blocked until M2-GATE and B-GH pass.

Retired surfaces remain retired:

- API v1 distribution/support;
- legacy CLI package and standalone CLI image;
- public npm packages;
- Docker Hub images;
- legacy website publication; and
- legacy automatic or otherwise unapproved branch/tag-triggered publication.

The future signed Helm OCI chart is an M6 artifact. No package is approved for
external distribution. A later package exception requires a named consumer and
acceptance test and may target GitHub Packages only.

### Branch and GitHub contract

`main` is the target canonical default branch. M2-02 owns the coordinated GitHub
rename and must restore required checks and conversation-resolution protection
on `main` before deleting the old branch. Publication, environments, GHCR
visibility, signing identity, and deployment credentials remain B-GH external
gates.

### Vulnerability and license contract

`docs/security/vulnerability-license-policy.md` is the governing M2 policy. In
summary:

- unaccepted critical/high or unknown-severity vulnerabilities block;
- verified secrets always block;
- missing, malformed, stale, or wrong-subject reports block;
- exceptions are exact, owned, approved, visible, and expiring;
- unknown, missing, prohibited, or obligation-unresolved licenses block
  distributed artifacts; and
- raw reports are retained without removing findings, while evaluation output
  records accepted exceptions.

## Evidence

### Exact runtime

Node `v24.19.0` (`Krypton` LTS, released 2026-08-03) was selected from the
official Node release index. The prototype verified the official SHA-256 for the
Linux x64 archive.

### Yarn 4 / Lerna 10 prototype

- Node `24.19.0`, Yarn `4.18.0`, Lerna `10.0.0`.
- Cold Yarn v1 lock conversion/install: 130.8 s.
- Clean immutable install with warm global cache and absent `node_modules`: 29.8
  s.
- All 14 workspaces discovered by Lerna 10.
- Compile reached the same legacy management-console Webpack 4 OpenSSL failure
  as Yarn 1/Lerna 4.
- Tests reached the same missing local PostgreSQL/MinIO integration prerequisite
  as the legacy baseline.
- Lock conversion rewrote the format: 19,093 to 29,121 lines.
- Primary prototype paths: `.yarnrc.yml`, `.gitignore`, `package.json`,
  `lerna.json`, `staticdeploy/package.json`, and `yarn.lock`.

### pnpm prototype

- Node `24.19.0`, pnpm `11.22.0`.
- Cold frozen install: 34.8 s; repeated frozen install: 1.0 s.
- Compile and lint passed after compatibility configuration; 794 non-external
  tests passed.
- Required 20 changed paths, workspace-link configuration, script rewrites,
  `shamefullyHoist`, an install-script allowlist, and the same Webpack OpenSSL
  bridge.
- The strict layout exposed an undeclared `@types/bluebird` dependency and one
  existing acorn/terser peer mismatch.

The pnpm result proves feasibility but not lower migration or maintenance
complexity.

## Known implementation gates

M2-02 must handle the coordinated package-manager, workflow, runtime pin,
branch, and Webpack bridge change. It must also replace Yarn 1-only
audit/license commands with supported M2 policy tooling and replace the
prototype's broad install-script bridge with the exact reviewed
package/version/script inventory. M2-02 cannot merge, and M2-GATE cannot pass,
while global script execution remains enabled.

The following are not accepted as regressions caused by the package-manager
choice, but remain mandatory M2-02 gates:

- full compile on Node 24 after the scoped Webpack bridge;
- full PostgreSQL/MinIO QA using disposable services;
- clean immutable install with no lockfile change;
- actionlint and both required Actions checks on the exact head; and
- no publication or deployment.

## Rollback

Before M2-02 merges, rollback is deletion of the prototype. After merge, revert
the package/config/lock/workflow commit, restore Yarn 1 and Node 14 baseline
pins, reinstall from the old lock, and rerun baseline QA. There is no schema,
object, package publication, or production deployment side effect.
